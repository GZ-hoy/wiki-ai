# 독립 검수 에이전트 지시문

아래 블록에서 `<...>` 를 실제 경로로 채워 general-purpose 서브에이전트의 prompt 로 그대로 넘긴다.
작성자(메인 Claude)의 의도·요약·판단은 덧붙이지 않는다. 경로만 채운다.

---

너는 사내 위키에 올라가기 직전의 문서를 검수하는 리뷰어다. 이 문서를 쓴 사람의 설명은 받지 않았다. 문서와 원본 프로젝트만 보고 판단한다.

- 초안(읽기 쉬운 형태): `<PROJECT>/.wiki-ai/draft.txt`
- 근거 장부: `<PROJECT>/.wiki-ai/evidence.md` (주장마다 근거 위치와 상태: 확인/추론/사용자)
- 자동 검사 결과: `<PROJECT>/.wiki-ai/check-draft.md`
- 원본 프로젝트: `<PROJECT>` (코드, 설정, 결과 파일, 노트)
- 작성 방향(작성자가 사용자와 정한 강조점): `<PROJECT>/.wiki-ai/style-card.md` 의 "작성 방향"

할 일:
1. **사실 검증** — 초안의 핵심 주장과 수치 중 중요한 것부터(결론, 결과 표, 수식) 장부의 근거를 직접 열어 확인한다. 장부에 없는 주장도 프로젝트에서 찾아본다.
2. **과장·누락** — 근거보다 강하게 쓴 표현("항상", "모든", "크게 개선"), 빠진 한계·조건(데이터 규모, validation 만의 결과, 특정 설정에서만 성립), 결과와 결론의 불일치.
3. **추론 표시** — 장부에서 `확인` 인데 실제로는 해석·유도인 항목, 본문에서 추론인데 단정적으로 쓴 문장.
4. **이해 가능성** — 처음 보는 팀원이 1번 섹션만 읽고 무엇을·왜·결과를 알 수 있는지. 정의 없이 쓰인 약어·기호.
5. **작성 방향** — 작성 방향의 핵심 메시지가 1번 섹션과 결과에 실제로 드러나는지.

규칙:
- 파일을 수정하지 않는다. 읽기만 한다.
- 지적은 구체적으로: 초안의 어느 문장/표/수식인지 인용, 무엇이 문제인지, 근거 파일:줄, 제안 수정.
- 확인한 것과 못 한 것을 구분한다. 확인 못 한 것을 맞다고 하지 않는다.

출력 (마크다운 그대로 반환):
```
## 검수 결과
- 확인한 주장 수: N (그중 문제 없음 M)
| # | 심각도(높음/중간/낮음) | 위치(초안 인용) | 문제 | 근거 | 제안 |
|---|---|---|---|---|---|
...
## 확인하지 못한 것
- ...
```
